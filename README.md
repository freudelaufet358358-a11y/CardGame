# SHIELD BREAK DUEL

ブラウザだけで遊べる、対戦型カードゲームです。
デュエル・マスターズの「マナ／シールド」と、遊☆戯☆王の「攻撃表示・守備表示／伏せカード」を
組み合わせたオリジナルルールで、**CPU対戦・2人対戦・デッキ構築**がすべて動きます。

**▶ 遊ぶ: https://freudelaufet358358-a11y.github.io/CardGame/**

> 本作は既存カードゲームのルールを参考にした**オリジナル作品**です。
> デュエル・マスターズや遊☆戯☆王の**カード名・イラスト・カードテキストは一切使用していません**。
> 収録カード40種はすべて本作用に書き下ろしたもので、絵柄は絵文字で表現しています。

---

## 特徴

- **インストール不要・アカウント不要** — URLを開けばすぐ遊べます
- **ビルド不要の素の HTML / CSS / ES Modules** — 依存パッケージゼロ、外部CDNも外部画像も使いません
- **CPU対戦**（やさしい／ふつう）と**2人対戦**（同じ画面で交互に操作、手札は自動で隠れます）
- **デッキビルダー** — 全40種から40枚を自由に構築し、ブラウザに保存して対戦で使えます
- **スマホ対応** — 縦画面に収まるレスポンシブレイアウト
- 4種類のプリセットデッキは、CPU同士 1,200戦の自動対戦で**勝率 47.5〜52.5%** に調整済み

## ルール概要

### 勝利条件
1. 相手のシールド5枚をすべて割り、**さらにもう一度攻撃を通す**（ダイレクトアタック）
2. 相手の**山札が尽きて引けなくなる**

### ターンの流れ
1. **アンタップ** — 自分のクリーチャーとマナが起きる
2. **ドロー** — 1枚引く（先攻の最初のターンは引かない）
3. **マナチャージ** — 手札から1ターン1枚だけマナゾーンへ。置いたマナはそのターンから使える
4. **メイン** — マナを払ってカードを使い、クリーチャーで攻撃する（召喚と攻撃の順序は自由）
5. **ターン終了** — そのターン限りのパワー修整が消える。手札上限はなし

### コスト
コストと同じ枚数のマナをタップし、**そのうち1枚以上はカードと同じ文明**である必要があります。
どのマナをタップするかは自動選択で、少数派の文明のマナが温存されます。

### クリーチャー ― パワーとガード、2つの表示形式

|  | 攻撃表示 | 守備表示 |
|---|---|---|
| 攻撃 | できる | できない |
| 攻撃を受けたときの値 | **パワー** | **ガード** |
| 相手に狙われるか | **タップ中のときだけ** | **いつでも** |

- 召喚したターンは攻撃できません（**召喚酔い**／スピードアタッカーは例外）
- **攻撃するとタップされます**。攻撃した直後は相手に狙われる隙になります
- 「攻撃表示で起きているクリーチャーは正面から殴れない」ため、盤面のクリーチャーを処理するには
  **相手が攻撃してタップした隙を突く／守備表示を狙う／除去カードを使う**のいずれかが必要です

### 戦闘
- 攻撃先は**相手プレイヤー（シールド）**か**相手クリーチャー**
- 相手は**ブロッカー**を1体タップして代わりに受けられます。ブロックは守りの行動なので、
  ブロッカーは表示形式にかかわらず**ガードの値**で戦います
- 値が大きいほうが勝ち、負けたほうは破壊。**同じ値なら相打ち**
- パワーが0以下になったクリーチャーは破壊されます

### シールドとシールドトリガー
- プレイヤーへの攻撃が通るとシールドが1枚割れ、**そのカードは持ち主の手札に入ります**
  （W・ブレイカーなら2枚）
- 割れたカードが**シールドトリガー**を持っていれば、**コストを支払わずその場で使えます**
- 攻撃してきたクリーチャーはタップされているので、
  「タップされているクリーチャーを破壊する」トリガーで返り討ちにできます

### 伏せカード（罠）
メイン中にコストを払って伏せ、**相手の攻撃宣言時**にコストなしで発動できます。

### キーワード能力
| 能力 | 効果 |
|---|---|
| ブロッカー | 相手の攻撃を、タップして代わりに受けられる |
| スピードアタッカー | 出したターンから攻撃できる |
| W・ブレイカー | シールドを1度に2枚割る |
| シールドトリガー | シールドが割れたとき、コストなしで使える |
| スレイヤー | バトルした相手を、パワーに関係なく破壊する |

### 文明
| 文明 | 役割 |
|---|---|
| ☀️ 光 | ブロッカー、相手のタップ、タップ中の相手の除去 |
| 💧 水 | ドロー、相手クリーチャーを手札に戻す |
| 🟣 闇 | 破壊、墓地の再利用、手札破壊 |
| 🔥 火 | スピードアタッカー、高いパワー、シールドブレイク |
| 🌿 自然 | マナ加速、最高クラスのパワー、マナ送りの除去 |

デッキは**ちょうど40枚**、同じカードは**4枚まで**です。

## 開発

### ローカルで動かす

ビルドは不要です。ES Modules を使うので、`file://` ではなく HTTP で配信してください。

```bash
python3 -m http.server 8000
# → http://localhost:8000/
```

### 自動テスト

ルールの検証は、ブラウザと同じモジュールを Node から読み込んで CPU 同士を戦わせる方式です。

```bash
node tools/selftest.mjs 1200
```

以下を自動で検査します。

- 全カード定義とプリセットデッキ4種の妥当性（40枚ちょうど・同名4枚まで）
- 例外が出ないこと、合法手が0件にならないこと、全試合が決着すること（無限ループ検出）
- 不変条件：各プレイヤーのカード総数が常に40枚、`uid` の重複なし、各ゾーンの枚数が負にならない
- デッキ別勝率・先攻後攻勝率・決着理由の内訳（バランスが偏れば警告）
- 難易度「やさしい」が「ふつう」より確実に弱いこと

### 構成

```
index.html                 単一ページ（タイトル／対戦準備／デュエル／デッキビルダー／遊びかた）
assets/css/style.css       全スタイル（外部フォント・外部画像なし）
src/
  data/cards.js            カード40種の定義
  data/decks.js            プリセットデッキとデッキ構築ルール
  engine/state.js          ゲーム状態の生成・複製・シード付き乱数
  engine/rules.js          ルール本体
  engine/effects.js        カード効果の解決
  ai/cpu.js                CPU思考ルーチン
  ui/duel.js               デュエル画面
  ui/deckbuilder.js        デッキビルダー
  ui/cardview.js           カード描画とカード詳細
  ui/rulesdoc.js           遊びかた画面
  ui/storage.js            localStorage への保存
  main.js                  画面遷移と対戦準備
tools/selftest.mjs         CPU同士の自動対戦テスト
```

**設計の要**は、`src/engine/rules.js` が公開する2つの関数だけでルールが完結していることです。

```js
legalActions(state)        // その時点で合法な行動の配列
applyAction(state, action) // 行動を適用した「新しい」状態（元の state は変更しない）
```

UI・CPU・自動テストがすべてこのAPIを通るため、
「CPU対戦」と「2人対戦」の違いは *手番のプレイヤーの指し手を自動で進めるかどうか* の1点だけになり、
UIコードを二重に書く必要がありません。CPUも「全合法手を評価して最善を選ぶ」だけで実装できます。

## 公開について（GitHub Pages）

静的ファイルがリポジトリ直下にあるため、次のどちらの方法でも公開できます。

1. **GitHub Actions（自動）** — `.github/workflows/pages.yml` が push のたびにデプロイします。
   `actions/configure-pages` の `enablement: true` により、Pages 設定も自動で有効化を試みます。
2. **ブランチから直接公開（手動・1操作）** — リポジトリの
   **Settings → Pages → Build and deployment → Source: Deploy from a branch** を選び、
   ブランチに `claude/card-game-project-s4ofnb`、フォルダに `/ (root)` を指定して Save。

ビルド成果物ではなくソースそのものを配信するため、どちらの方法でも同じものが公開されます。
