## 1. 前提と制約

### プロダクトの性質

デュエル・マスターズの「マナ／シールド」と遊☆戯☆王の「攻撃表示・守備表示／伏せカード」を
組み合わせた独自ルールの1対1カードゲーム。CPU対戦、同一端末での2人交互対戦、40枚のデッキ構築が
すべてブラウザ内で完結します。サーバー・アカウント・通信はありません。

### 変更してよい領域・してはいけない領域

| 区分 | 内容 |
|---|---|
| **変更してよい** | 見た目、レイアウト、情報の並び、操作手順、コピー、モーション、コンポーネント構造 |
| **変更に相談が必要** | ゲームルールそのもの（何が合法手かはエンジンが決定し、UI は表示と入力のみを担当） |
| **技術的な制約** | 外部画像・外部CDN・外部フォントを使わない方針（完全オフライン動作・依存ゼロが要件）。現状カードの絵柄は**絵文字1文字**。この方針自体は再検討の対象（[D-01](#d-01-カードの絵柄が絵文字1文字)） |
| **ビルド** | ビルド工程なし。CSS は単一ファイル、カスタムプロパティでトークン管理 |

### UI が担う責務

ルールエンジンは「その瞬間に選べる合法手の一覧」を返します。UI の仕事は次の3つだけです。

1. 盤面の状態を見せる
2. 合法手を選ばせる
3. 何が起きたかを伝える

不正な操作は原理的に発生しないため、**エラー表示やバリデーションUIは対戦画面に存在しません**
（デッキ構築画面にはあります）。

## 2. 用語辞書

ゲーム用語と画面上の要素の対応。コピーを書き換える際はこの語彙を崩さないでください。

| 用語 | 意味 | UI上の表現 |
|---|---|---|
| **シールド** | ライフに相当。5枚。中身は本人にも見えない | 裏向きカード（金枠）の横並び |
| **マナ** | コストの支払い元。手札から1ターン1枚置く | 小さな文明色チップ。使用済みは回転 |
| **バトルゾーン** | クリーチャーが出る場所。最大5体 | カードの横並び（最大の面積を持つ帯） |
| **伏せカード** | 罠。相手の攻撃時に発動 | 自分＝小型の表向きカード／相手＝裏向き |
| **タップ** | 使用済み・行動済みの状態 | カードを9°傾け、輝度を下げる |
| **攻撃表示／守備表示** | クリーチャーの向き。参照する数値が変わる | カード下部のテキスト＋守備は内側に青枠 |
| **パワー／ガード** | 攻撃時／防御時に使う数値 | カード最下段に2値並置（暖色／寒色） |
| **召喚酔い** | 出したターンは攻撃できない | カードを彩度低下（グレースケール35%） |
| **シールドトリガー** | 割られた瞬間にコストなしで使える逆転札 | 専用のフェイズUI＋トースト |
| **文明** | 光・水・闇・火・自然の5色 | カード枠色／コストバッジ／絵文字 |

## 3. 画面構成と遷移

単一 HTML 内の5セクションを表示切り替えするだけの構成です。
**URL は変化せず、ブラウザの戻るボタンは効きません**（[D-06](#d-06-履歴url中断復帰がない)）。

| 画面 | ID | 役割 | 出口 |

## 4. 盤面レイアウト

### 配置の原則：卓上の鏡写し

上下で完全な鏡像とし、**シールドが最も中央寄り**になるよう並べています。
実際の卓上で「自分の前にシールドを並べて相手と向き合う」配置の再現です。
これにより、攻撃時のクリック導線（自分の場 → 中央 → 相手のシールド）が最短になります。

```
━━━━━━━━━━━━━━━ 相手側 ━━━━━━━━━━━━━━━
  情報バー      名前 / シールド / 手札 / マナ / 山札 / 墓地
  マナゾーン    ─────────────────────  伏せゾーン
  バトルゾーン  最大5体・min-height 124px
  シールド      裏向き5枚 ← 攻撃の対象領域
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  中央バー      フェイズ表示 / ログ / 投了
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  シールド      裏向き5枚
  バトルゾーン  ここから攻撃を宣言する
  マナゾーン    ─────────────────────  伏せゾーン
  情報バー      手番中は金枠でハイライト
  手札          表向き・横スクロール
  行動バー      文脈に応じたボタン群
━━━━━━━━━━━ 自分側（視点） ━━━━━━━━━━━
```

2人対戦では手番交代のたびに視点が反転し、**常に「操作する人が下」**になります。
CPU対戦では視点は固定です。

### ゾーンの寸法

| ゾーン | クラス | 最小高 | 幅の扱い | あふれた場合 |
|---|---|---:|---|---|
| バトルゾーン | `.zone--field` | 124px | 全幅 | 横スクロール |
| シールド | `.zone--shields` | 60px | 全幅 | 横スクロール |
| マナ | `.zone--mana` | 44px | 可変（`flex:1`） | 横スクロール |
| 伏せ | `.zone--traps` | 44px | 最小96px | 横スクロール |
| 手札 | `.hand` | 124px | 全幅 | 横スクロール |
| 行動バー | `.actionbar` | 40px | 全幅 | 折り返し |

盤面全体は `max-width: 1100px` で中央寄せ。上記の合計は約 **790px** で、
高さ 860px のビューポートに行動バーまで収まるよう設計されています。

> ⚠️ **行動バーが画面外に出ると操作不能に見える**ため、要素の追加には注意が必要です
> （[D-07](#d-07-盤面の縦方向に余裕がない)）。

### 情報バー

```
┌──────────────────────────────────────────────────────────────────┐
│ あなた   🛡 シールド 5   🃏 手札 6   💠 マナ 3/5   📚 山札 24   ⚰️ 墓地 2 │
└──────────────────────────────────────────────────────────────────┘
  ↑ .side__info.is-turn のときは金枠 + inset 1px の金ライン
```

5つの数値を等価に並べています。マナのみ「使用可能／総数」の分数表記です。

## 5. カードの構造

カードは幅 `92px`（狭い画面では `74px`）の固定幅、角丸 8px、内側余白 4px。
高さは内容で決まり、クリーチャーで約 130px です。

```
      ┌─────────────────┐ ← border 1px：文明色
      │ ⑦          🔥  │◄─ .card__top：コストバッジ（19px円・文明色塗り）＋文明絵文字
      │                 │      ┌──── .card__kw：能力バッジ（右上に食い込む）
      │       🐉        │◄─ .card__art：絵文字 27px
      │                 │
      │  灼熱竜         │◄─ .card__name：10px / 700 / 最小2.2行
      │  ヴォルカニクス  │
      ├─────────────────┤
      │ ⚔️9000   🛡4000 │◄─ .card__stats：左＝パワー（暖色）／右＝ガード（寒色）
      └─────────────────┘
       92px（狭い画面 74px）
```

### 構成要素

| 要素 | クラス | 仕様 |
|---|---|---|
| コストバッジ | `.card__cost` | 19px 円・文明色の塗り・暗色文字・800weight |
| 文明記号 | `.card__civ` | 右上に絵文字 12px |
| 絵柄 | `.card__art` | 絵文字 27px（狭い画面 21px） |
| カード名 | `.card__name` | 10px / 700 / 行間1.25 / 最小2.2行 / はみ出しは切り捨て |
| パワー・ガード | `.card__stats` | 左右に振り分け。暖色 `#ffb9a3` / 寒色 `#a9d8ff` |
| 種別ラベル | `.card__kind` | 呪文・罠、および場では表示形式を表示 |
| 能力バッジ | `.card__kw` | 右上に食い込む丸ピル。1文字略号 |

### 能力の略号

| 略号 | 能力 | 意味 |
|---|---|---|
| `ブ` | ブロッカー | 攻撃を代わりに受けられる |
| `速` | スピードアタッカー | 出したターンから攻撃できる |
| `W` | W・ブレイカー | シールドを2枚割る |
| `ST` | シールドトリガー | 割られた瞬間に無料で使える |
| `ス` | スレイヤー | バトルした相手を必ず倒す |

### バリエーションと裏向き要素

| 種類 | クラス | 寸法 | 用途 |
|---|---|---|---|
| 通常カード | `.card` | 92px幅（狭幅74px） | 手札・場・一覧 |
| ミニカード | `.card--mini` | 58px幅 | 自分の伏せカード、対象選択の候補 |
| シールド | `.cardback--shield` | 40×56（狭幅32×45） | 金枠・🛡 |
| 相手の伏せ | `.cardback--trap` | 40×56 | 紫枠・⁉️ |
| 相手の手札 | `.cardback` | 40×56 | 青枠・🂠 |
| マナチップ | `.manachip` | 26×34 | 文明色・絵文字のみ |

マナは文明さえ判別できればよいためカードではなくチップで表現し、盤面の情報量を抑えています。

## 6. 状態マトリクス

> **この節が設計上いちばん重要です。**
> カードは最大で5つの状態が同時に成立し、それらが視覚的に衝突しないことが要件になります。

| 状態 | 意味 | 現在の表現 | 同時に成立しうる状態 |
|---|---|---|---|
| `.is-tapped` | 使用済み・攻撃済み | 9°回転 + 0.94倍 + 輝度72% | defense / target / sick |
| `.is-defense` | 守備表示 | 内側に2pxの青枠 `#7fb4ff` ＋ 下部テキスト | tapped / target / selected |
| `.is-selected` | 選択中 | 金の実線アウトライン 2px | defense |
| `.is-target` | 効果・攻撃の対象候補 | 緑の破線 2px ＋ 1.1秒の点滅 | tapped / defense |
| `.is-actionable` | いま何かできる手札 | 金の細枠（不透明度55%） | selected |
| `.is-sick` | 召喚酔い（攻撃不可） | 彩度 -35% ＋ 輝度85% | defense |
| `.fx-flash` | 攻撃宣言中のクリーチャー | 金の発光 0.55秒 | tapped |

```css
/* 実装値（assets/css/style.css より） */
.card.is-tapped     { transform: rotate(9deg) scale(.94); filter: brightness(.72); }
.card.is-defense    { box-shadow: var(--shadow), inset 0 0 0 2px #7fb4ff; }
.card.is-selected   { outline: 2px solid var(--gold); outline-offset: 2px; }
.card.is-target     { outline: 2px dashed var(--ok); outline-offset: 2px;
                      animation: pulse 1.1s infinite; }
.card.is-sick       { filter: grayscale(.35) brightness(.85); }
.card.is-actionable::after { border: 1px solid var(--gold); opacity: .55; inset: -3px; }
```

> ⚠️ **設計上の注意**
> `.is-tapped` と `.is-sick` はどちらも「今は動かせない」を意味しますが、表現が
> 回転と彩度低下で分かれています。また輝度72%と85%の差は暗い盤面では読み取りにくい状態です
> （[D-05](#d-05-タップ召喚酔いの区別が弱い)）。

### ゾーンの状態

| 状態 | クラス | 表現 |
|---|---|---|
| 通常 | `.zone` | 破線1px `rgba(80,96,150,.4)` |
| 対象候補 | `.zone.is-targetzone` | 緑の破線2px＋緑の薄い塗り＋点滅。**シールド列そのものがクリックターゲット** |
| 空 | `.zone__empty` | 説明テキストのみ（例：「バトルゾーンは空」）。アイコンなし |

ゾーンの枠線のみ**破線**で、「置き場所」であることを実線の要素と区別しています。

## 7. 操作モデル

すべての操作が **「対象を選ぶ → 何をするか選ぶ → （必要なら）効果の相手を選ぶ」** の
3段階に統一されています。手札・場のどちらでも同じ手順です。

```
  ①カードをクリック          ②行動バーに選択肢          ③対象を選ぶ（必要時のみ）
  ┌──────────┐             ┌────────────────┐        ┌──────────────────┐
  │ 金枠が付く │  ────────►  │ ⚔️ 攻撃する      │ ─────► │ 候補が緑の破線で   │
  │ .is-selected│            │ 🔄 表示形式を… │        │ 点滅 .is-target   │
  └──────────┘             │ 選択解除        │        │ 「やめる」で中断可  │
                            └────────────────┘        └──────────────────┘
```

### 省略ルール

- 選択肢が1つで対象も取らない場合、**手順②を飛ばして即実行**します。
- **攻撃しかできないクリーチャー**を選ぶと、手順②を飛ばして直接対象選択に入ります
  （最も頻度の高い操作のクリック数を減らすため）。

### 行動の種類

| ラベル | 対象 | 出現条件 | 対象選択 |
|---|---|---|---|
| 💠 マナに置く | 手札 | そのターン未チャージ | なし |
| ⚔️ 攻撃表示で召喚 | 手札 | クリーチャー・コスト支払可・場に空き | 召喚時効果があれば |
| 🛡 守備表示で召喚 | 手札 | 同上 | 同上 |
| ✨ 唱える | 手札 | 呪文・コスト支払可・対象が存在 | 効果による |
| ⁉️ 伏せる | 手札 | 罠・コスト支払可・伏せ枠に空き | なし |
| 🔄 表示形式を変える | 場 | 未タップ・召喚ターン以外・1ターン1回 | なし |
| ⚔️ 攻撃する | 場 | 攻撃表示・未タップ・召喚酔いなし | 必須 |

### 攻撃対象の選び方

攻撃対象は**相手のシールド列**か**相手クリーチャー**です。
ただしクリーチャーを狙えるのは、そのクリーチャーが**タップ中か守備表示のとき**だけという
ルールがあり、**狙えないクリーチャーは点滅しません**。つまり「光っている場所が全て」です。

### 対象が盤面に見えない場合

墓地からの回収など、盤面に表示されていないカードを対象にする効果では、
候補が**行動バーにミニカード（58px）として並びます**。

### カード詳細の閲覧

任意のカードにマウスを乗せる（タッチでは**長押し380ms**）と、**232px 幅**のポップオーバーが
隣に出ます。カード名・文明・コスト・種別・パワー／ガード・効果テキスト・キーワード解説を含みます。
画面端では自動的に反対側へ回り込みます。タッチでは 2.2 秒後に自動的に消えます。

## 8. フェイズ別UI

行動バーの中身はフェイズで完全に入れ替わります。**盤面自体は変わりません。**

| フェイズ | 操作者 | 行動バーの内容 |
|---|---|---|
| `main` | 手番プレイヤー | 選択に応じた行動ボタン＋常時「ターン終了」 |
| `defend` | 攻撃された側 | 攻撃内容の説明＋罠／ブロック／「攻撃を通す」 |
| `trigger` | シールドを割られた側 | 発動したカードの実物＋「使う」／「使わない」 |
| `gameover` | — | 空。結果オーバーレイに置き換わる |

### 防御フェイズ

```
「灼熱竜 ヴォルカニクス」が シールド を攻撃！ 応じますか？
[ 罠：呪縛の罠 ] [ 🛡 白翼の守護者 セラフィナ でブロック（ガード5000） ] [ 攻撃を通す ]
                                                                          ↑ primary
```

ブロック候補はガード値を併記します。
同名カードが2体いると**まったく同じラベルが2つ並びます**（[D-04](#d-04-防御フェイズで同名カードが区別できない)）。

### シールドトリガー

```
シールドトリガー発動！  [ミニカード]  [ 使う ] [ 使わない（手札に残す） ]
                                       ↑ primary
```

対象がおらず発動できない場合は「使う」が消え、
**「― 効果の対象がいないため、このトリガーは使えません」**と理由を明示したうえで、
ボタンが「**手札に加えて続ける**」（primary）に変わります。

### オーバーレイ

| 種類 | 出る条件 | 内容 | 背景 |
|---|---|---|---|
| 手番の受け渡し | 2人対戦でターンが移った瞬間 | 次の人の名前＋開始ボタン | **完全不透明**（手札を隠すため） |
| 結果 | 決着の0.7秒後 | 勝敗＋決着理由＋再戦／タイトル | 86%の暗幕＋ぼかし |
| ログ | 「ログ」ボタン | 右からのパネル（最大360px）。種別で色分け | なし（サイドパネル） |

ログの色分け：ターン＝金／ブレイク・トリガー＝橙／破壊＝赤／勝利＝緑。

### 通知（トースト）

画面上部18%の位置に中央寄せ、金枠の丸ピル。**1.5秒**で消滅。
シールドブレイク・トリガー・罠・呪文・破壊で発火します。
シールドブレイク時は**盤面全体が0.35秒振動**します。

### CPU の思考演出

| 局面 | 待ち時間 |
|---|---:|
| 通常の1手 | 620ms |
| マナチャージ・ターン終了 | 260ms |
| 決着 → 結果表示 | 700ms |

## 13. 未解決の設計課題

現行実装で意図的に保留した、あるいは実装上の都合でそうなっている点です。
**ここが引き継ぎの本題です。** 重要度順に並べています。

### D-00. アクセシビリティが未着手

> 🔴 **最優先**

現状 `aria-*` 属性 **0件**、`role` **0件**、`tabindex` **0件**、キーボードイベント **0件** です。
カードは `<button>` ではなく `<div>` にクリックハンドラを付けた実装で、
**キーボードだけでは1手も指せません**。スクリーンリーダーでは盤面が読めません。

**判断してほしいこと**
フォーカス可能な単位の粒度（カード単位か、ゾーン単位＋矢印キー移動か）、
フォーカスリングの見た目（既に金＝選択・緑＝対象で埋まっているため第3の表現が要る）、
盤面状況の読み上げ文言の設計。

### D-01. カードの絵柄が絵文字1文字

> 🟠 **要方針決定**

外部アセットを持たない方針の帰結です。OS・ブラウザで字形が変わり、同系統のカードが
似た絵文字になりがちで（例：闇の 🟣 は環境により無地の円に見える）、
40種の識別性とゲームらしい重厚さの両方で弱点です。

**判断してほしいこと**
絵文字を洗練させて使い続けるか、CSS/インラインSVGで文明ごとの紋章体系を作るか。
後者なら40種分の作図が必要になるため、「文明×種別」の9〜15パターンに減らす案も含めて検討をお願いします。

### D-02. 狭い画面でパワー／ガードが色だけの区別になる

> 🟠 **可読性**

620px 以下では幅が足りず ⚔️🛡 の記号を非表示にしています。結果、2つの数値は
暖色（`#ffb9a3`）と寒色（`#a9d8ff`）と左右の位置だけで区別されます。
色覚特性によっては判別できません。**数値はゲームの勝敗を直接左右します。**

**判断してほしいこと**
記号を細いテキスト字形に置き換える／上下2段組にする／攻撃表示のときは片方だけ強調するなど、
狭幅での両立案。

### D-03. 金色が5つの意味を兼務している

> 🟠 **意味の衝突**

`#e7c86b` は「手番プレイヤーの枠」「選択中のカード」「操作可能な手札」「主要ボタン」
「シールドの枠」「トースト」に同時に使われ、さらに光文明（`#e8c766`）とほぼ同色です。
光文明のブロッカーを選択すると、枠・コストバッジ・選択枠がすべて金になります。

**判断してほしいこと**
状態色（選択・操作可能）とブランド色（主要操作）と文明色を分離した配色設計。

### D-04. 防御フェイズで同名カードが区別できない

ブロック候補をテキストボタンで列挙しているため、同名のブロッカーが2体いると
まったく同じラベルのボタンが2つ並びます。機能的には等価なので実害は小さいものの、
何を選んでいるのか分かりません。

**判断してほしいこと**
防御選択もメイン同様に盤面ハイライト方式へ統一するか、ボタンにミニカードを添えるか。

### D-05. タップ／召喚酔いの区別が弱い

どちらも「今は動けない」ですが、9°の回転（輝度72%）と彩度低下（輝度85%）という
別種の表現になっています。暗い盤面で、しかも小さいカードでは差が読めません。
**初心者が「なぜ攻撃できないのか」を理解できない主因**です。

**判断してほしいこと**
状態の視覚語彙の整理。「回転＝使用済み」「別の何か＝まだ動けない」の切り分け。

### D-06. 履歴・URL・中断復帰がない

画面切り替えは DOM のクラス操作のみで、URL は変わりません。
ブラウザの戻るでページを離脱し、対戦中のリロードで進行が失われます
（自作デッキは localStorage に残ります）。

**判断してほしいこと**
ハッシュルーティングの導入可否、対戦途中の保存・復帰をUXとして持つべきか。

### D-07. 盤面の縦方向に余裕がない

11のゾーンを縦に積む構造上、高さ860pxで合計約790pxとほぼ余白がありません。
要素を1つ増やすと行動バーが画面外に落ち、操作不能に見えます（実際に一度発生しました）。

**判断してほしいこと**
マナと伏せを情報バーに統合する、シールドを枚数表示＋展開式にするなど、
恒久的に高さを確保する構造案。

### D-08. 空ゾーンと初回導線

空のゾーンは「バトルゾーンは空」等のテキストのみ。チュートリアルはなく、
初回プレイヤーは「遊びかた」を読むか、手札を触って推測する必要があります。
操作案内は行動バーの1行（「カードをクリックして行動を選びます」）だけです。

**判断してほしいこと**
初回のみのコーチマーク、あるいは最初の1ターンを誘導する仕組みの要否。
